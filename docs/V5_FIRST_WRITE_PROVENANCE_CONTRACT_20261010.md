# V5 First-Write Provenance Contract — OFFLINE DESIGN ONLY

2026-10-10 JST. Scope: `v5/official_first_write_storage.py` + `v5/official_first_write_executor.py`. **No DB/DDL/HTTP execution or production authorization.**

## Objective and current boundary
- Preserve source-kind / race-id / resource-key / exact official source URL + original response-body SHA-256 and bytes, request-start and body-completion times, and one canonical first row. Existing `INSERT_FIRST` uses `ON CONFLICT (resource_key) DO NOTHING`, then `READ_FIRST` compares raw bytes/hash/clocks within the same transaction. This proves only consistency of that transaction against the read row.
- Currently `stored_at timestamptz NOT NULL DEFAULT now()` exists in the *undeployed* DDL, but `READ_FIRST` and executor `READ_COLUMNS` omit it. Current result intentionally returns `first_observed_at=None`, `first_write_confirmed=False`, `forward_eligible=False`.
- **Critical threat boundary:** a caller may forge HTTP clocks/body, the client and DB clocks differ, DB owners/admins can bypass ordinary ACLs, and a consistent self-read is not an independent attestation. `now()` in PostgreSQL is the **transaction-start** timestamp, not necessarily actual insert or commit time; it must never be relabeled as first observed or as immutable commit time.

## Required provenance proof (future, separately approved design; NOT implemented)

1. **Exact DB readback and row identity** — Extend a prospective read-only verification view/query to return `resource_key, source_kind, race_id, source_url, request_started_at, response_completed_at, raw_bytes, raw_sha256, stored_at`. Require typed timezone-aware DB timestamp `stored_at`, key/source/URL/race identity, 64-char hash with `sha256(raw_bytes)`, byte equality to *original captured* response and immutable response-completion clock. Verify `READ_FIRST` and executor column order evolve together. Reject absent/NULL/malformed, mismatched or retroactively modified rows. Do not infer source authenticity from hash equality.
2. **DB-owned timestamp provenance** — Writer may not provide `stored_at` or overwrite it; timestamp must be assigned by trusted DB mechanism with separately reviewed semantics. The present `DEFAULT now()` value is *only* transaction start; it can predate INSERT, must not be used as actual commit evidence or latest-allowed cut-off proof on its own. Future choices (e.g., audited server clock at write plus post-commit acknowledgment) require a separate schema/security review; no automatic DDL change is authorized here.
3. **Append-only ACL and role separation** — A dedicated non-owner capture role may have only narrowly column-scoped `INSERT` on the approved table (excluding server-owned `stored_at`) and required restricted read/sequence rights; **no `UPDATE`, `DELETE`, `TRUNCATE`, `ALTER`, `DROP`, table ownership, SECURITY DEFINER bypass or privilege to grant itself rights**. An independent auditor has read-only access; migrations/ownership use a separate controlled principal. Audit effective grants, inherited memberships, default/public privileges, runtime credentials and privileged function paths. Document owner/superuser escape hatch explicitly: PostgreSQL grants alone do *not* render a row tamper-proof against DB administrators.
4. **Commit + independent auditor** — A second principal must read the canonical row **after commit in a separate transaction**, verify identity, bytes/hash, `stored_at`, approved role policy and trusted externally captured request/body-completion evidence. Bind the attestation to resource key, immutable digest, official race, source URL type, writer identity, DB/auditor identity, DB transaction evidence and independent observation time. Store audit evidence under a separately controlled append-only trust domain (no need to keep raw racer identities in diagnostic logs). An auditor merely echoing writer-supplied flags, clocks or hash is insufficient.
5. **Predecision and official status are separate gates** — Require independently sourced official race deadline and decision cutoff, clock provenance/offset quality, response completion **strictly before** decision cutoff, independently verified committed first-write/readback/audit **also before cutoff** for the intended use, no backdated/stale capture, and source update/as-of freshness checks. A later successful readback cannot retroactively make an unobserved earlier Forward decision valid. If time provenance cannot be independently established, **HOLD**.
6. **Six-active proof is additional, not interchangeable** — Official affirmative six lane–racer-bound active-start status schema is not verified (`APPROVED_POSITIVE_SOURCE_SCHEMAS` empty). A perfect first-write provenance check by itself still cannot permit beforeinfo first-write/Forward/BUY; exhibition 6/6, listed 6 racers, no `欠場`, odds/sales or caller `active=True` do not change this.

## Proposed review outputs and fail-closed invariants
- Future pure checker input: a frozen HTTP receipt proposal, original row and separately signed/verified DB-owner/auditor evidence; report only booleans/reason codes plus anonymous race/source-key and hashes, **not** raw bytes, registration IDs, secrets or response page text.
- Reason codes to plan for: `STORED_AT_NOT_READ_BACK`, `DB_ROLE_POLICY_UNVERIFIED`, `POSTCOMMIT_AUDITOR_MISSING`, `SOURCE_RECEIPT_UNAUTHENTICATED`, `CLOCK_OR_DEADLINE_UNVERIFIED`, `CAPTURE_AFTER_CUTOFF`, `COMMIT_AFTER_CUTOFF`, `ROW_MUTATED_OR_COLLIDED`, `OFFICIAL_SIX_ACTIVE_NOT_PROVEN`.
- With only current code inputs, **all** cases must output `first_observed_at=None`, `first_write_confirmed=False`, `six_active_starts_confirmed=False`, `beforeinfo_first_write_eligible=False`, `forward_eligible=False`, `buy_eligible=False`; reject caller-provided claims. A future attestation must be promoted only after independent source/role audit and explicit change review.

## Narrow fake/mock-only acceptance test plan (not run)
1. Valid *synthetic* frozen receipt + same-tx identical row **without independently attested `stored_at`** => HOLD; no first-observation assertion.
2. DB mock omits `stored_at`, returns wrong type, or tampers with it => reject; verify column order and distinct pre/post-commit read results.
3. Duplicate key with different bytes/hash/timestamp, or apparently identical data after UPDATE mock => collision/tampering fail closed; duplicate identical row never proves first-ever observation.
4. Simulated capture role has inherited `UPDATE`/`DELETE`/owner/admin rights or can set `stored_at` => policy unverified/blocked; only separately audited least-privilege grants qualify.
5. Simulated `now()` transaction start earlier than delayed INSERT/commit, and commit acknowledgment after cutoff => reject; do not use `stored_at` alone for predeadline proof.
6. Client HTTP completion or independent audit after decision cutoff; missing timezone or clock-quality metadata; unknown official deadline => HOLD.
7. Writer-supplied fake auditor token/boolean/signature, or an auditor with writer-controlled storage => reject as not independent.
8. All synthetic receipt/ACL/timing checks nominal but no authoritative six-active official field => Forward/first-write/BUY still HARD HOLD.
