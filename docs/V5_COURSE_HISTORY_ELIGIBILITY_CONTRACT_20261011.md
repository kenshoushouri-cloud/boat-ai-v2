## 元コードから直接確認した事実

- `research/v5_strong_core_calibration_pg.py`：結果側 `hist` をレース単位で判定後、`hday[day]` に有効な `(racer,start_course,finish_position)` **行ごと**格納。`for day in sorted(days)` でその日の予測特徴を**更新前**Counterから作り、その日の予測が終わってから `cs/ct/rcs/rct` を更新。
- `hist` は予測可能な `days[day]` のレースに限定されず、**特徴不足で予測対象外だったレース**の正常な結果行も含み得る。
- ただし研究コードの更新ループは `days` が存在する日に限る。**その日に有効な予測対象が0件なら、その日の `hday` も適用されない**（元実装上の制限）。
- `research/v5_lc_rf_exrank_rc_plus_opponent_pg.py` は公式Kで確認した全レースVOIDを除外し、`filter_postrace_primary_training` 内で結果6行・事故旗・着順コード等を `classify_historical_incident` に渡す。正常レースの `hday` 生成時は有効なコース/着順の**行単位**フィルタ。
- `research/historical_incident_eligibility.py` の `NO_INCIDENT_EVIDENCE` は、6艇別結果の1〜6号艇が揃い、通常のfinish_statusがあり、`is_flying/is_late` が全艇明示Falseであることを確認するが、**予測前に観測済みであることも返還なしも保証しない**。結果ステータスでは取消の表示を検出するが「その他の文字列は公式確定」とは判定しない。
- 新 `v5/offline_prior_day_counter_update.py` は、予測対象の結果が公式・事故なし・返還なしのとき**6艇全コース行一括で**更新するため、4種類 `cs/ct/rcs/rct` だけ元研究と採用範囲が異なる。前工程の模擬テストで差を再現済み。

## 推奨する次期オフライン契約（実装未着手）

1. **母集団を別々に固定する。** (A) 対象日の全レース予測/NO-BUY/保留を含む意思決定・決済台帳、(B) 主予測学習9 Counterの適格レース、(C) コース履歴4 Counterの適格**行**。B・Cの採否をAに波及させてはいけない。
2. **二段階バリアを守る。** 対象日の全予測とNO-BUYを固定し、当日のどの結果も推論へ使わない。後日取得結果だけを翌日以降のCounterへ反映。レース日付・同日入力全件・ベース状態指紋・二重適用防止を検査する。予測対象0件の日も、完全日付台帳が確認できなければ勝手に「全件処理済み」とは扱わない。
3. **Cには予測特徴の完全性を要求しない。** 展示・recent_formが欠損しても、事故や結果の独立検証に合格したレースのコース履歴は候補。Aには残す。未確定・VOID・事故レースをCへ流用しない。
4. **Cのレース単位の肯定証拠。** 対象日一致、公式結果として確定、別途K-VOID該当なし、6艇別結果が揃い重複なし、finish_statusが通常、F/Lフラグが各艇Falseと**明示**、結果ステータスの取消等がない。条件不明は `HOLD`。結果の`NO_INCIDENT_EVIDENCE`だけで `OFFICIAL` や `refund_boats=()` と推論しない。
5. **返還・事故は別証拠。** `refund_boats=None` は「不明」で、空配列へ置換しない。予測・収支では必ず返還/VOID/F/L/PENDINGを保持。Cで元研究への近似採用を狙う場合も返還未知を学習可と短絡せず、結果原本確認までHOLDする。元研究と異なる場合は理由を付けて差分計上。
6. **Cの行単位集計。** 肯定レース内でも `racer_number>0`・`start_course∈1..6`・`finish_position∈1..6` の行だけ、`cs[course]` と `rcs[course][racer]` を+1、着順≤3なら `ct[course]` と `rct[course][racer]` も+1。無効行は理由付きで除外し、全行一律で落とさない。重複/矛盾等、研究コードが見逃す可能性がある不整合は安全側でHOLDし「研究式完全同値」と誤表示しない。
7. **監査用内訳が必要。** 日付別・Counter種類別の増分、正常/未確定/事故/返還不明/特徴不足/無効行/履歴のみ採用件数、元研究との不一致理由を保存できる形にする。実結果のfirst_observed_atおよび過去の証拠時点は別項目で検証し、後日収集データを締切前証拠に偽装しない。
