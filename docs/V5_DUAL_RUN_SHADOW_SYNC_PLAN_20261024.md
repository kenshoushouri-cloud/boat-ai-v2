## 二段階の並行検証（速さと真正性を両立）
**A. 即開始可能：既存13 VIEWからのV5読取・紙上予測・2025-07以降バックテスト**。DB構造を変えずread-onlyで開始する。学習と結果評価ではイベント時刻・取得時刻・prediction freeze/cutoffを厳密に区別する。現時点で「捕捉時点の立証がない歴史データ」は実証ROIに含めない。

**B. stageを永続作成する際：**
1. stage12のDDLを原本への変更なしに限定し、予め定義した安全ゲート・復旧手段・操作範囲の承認後に実行。venuesを再作成・再コピーしない。stage schema/PK/index/default/sequence権限を検証。
2. 現行収集を動かしたまま、1〜500行など小さな範囲で低負荷の原本→stage一方向初回複製。負荷・WAL・空きディスク・タイムアウトを監視。先に結果/出走/レース、後で重いスナップショット。
3. コピー中のUPDATE/DELETEも取りこぼさないよう、**final consistency snapshot／完全主キー集合に基づくINSERT/UPDATE/DELETE差分の再照合**を実施。単純な最終日付カーソルは不十分。独立したstage採番シーケンスを維持。
4. Stageの遅延秒数、レース単位の6艇揃い・120券揃い、原本との件数/キー/ハッシュ/時点一致、真の初回観測・予測締切時刻を検査。
5. V5は当面`shadow/paper`として稼働。DBも現行収集も2重書込なし。遅延・欠損・予測入力不足では`HOLD/NO_BUY`。モデル指標をold/newで比較し、BUYには進まない。
